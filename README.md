# Тестовое задание для n8n-инженера

Привет! Это задание - проверочный кейс перед тем, как ты получишь доступ к боевому проекту Goodini. Я хочу понять, как ты работаешь с чужим кодом и как мыслишь при рефакторинге.

## Что за проект

Goodini - это AI-пайплайны генерации видеоконтента для недвижимости. Стек: n8n, Postgres, MinIO, Redis, ffmpeg, внешние API (Replicate, Google AI Studio, ElevenLabs, OpenRouter). На сервере, всё в docker-compose.

Основной обзор - в `00-vision.md` и `README.md`. Можно полистать для контекста, но в задании это не нужно. Эта документация будет предоставлена позже.

## Структура задания

Задание состоит из двух частей плюс setup.

### Часть 1: Code Review

В папке [`part-1-code-review/`](part-1-code-review/) лежат три n8n-воркфлоу. В каждом я заложил несколько проблем, от security до n8n-специфичных граблей.

Что нужно:
1. Импортировать каждый воркфлоу в локальный/серверный self-hosted n8n.
2. Найти все проблемы.
3. Расставить по приоритету (high / medium / low).
4. Реализовать фиксы для топ-3. Любые 3 из всех найденных.

Подробности и формат сдачи - [`part-1-code-review/README.md`](part-1-code-review/README.md).

### Часть 2: Forensic Combine Worker

В папке [`part-2-forensic/`](part-2-forensic/) - один из наших боевых воркфлоу `Combine Worker - MVP2.0`. Это финальная нода пайплайна: собирает видеоклипы, накладывает озвучку и музыку, опционально оверлеит аватар, заливает результат в MinIO.

Что нужно:
1. Разобрать воркфлоу - что делает каждая группа нод, в каком порядке, какие зависимости между нодами.
2. Найти 3 потенциальных слабых места,что угодно. Недостающая обработка ошибки, edge case, ресурсная утечка, плохая читаемость.
3. Предложить 2 рефакторинга с обоснованием.
4. Реализовать одну задачу из трёх на выбор - см. подробности в [`part-2-forensic/README.md`](part-2-forensic/README.md). Все три про ffmpeg. 

### Setup

Минимальный docker-compose для запуска n8n + Postgres + MinIO локально - в [`setup/`](setup/). Инструкция там же.

## Что ждут от тебя

- Импортируешь воркфлоу, прокликиваешь, разбираешься.
- Сдаёшь два markdown-отчёта по шаблонам в каждой части `deliverable-template.md`.
- Прикладываешь обновлённые JSON-файлы (с фиксами для Part 1 и реализованным рефакторингом для Part 2).
- Можно одним zip, можно GitHub репо.
- @username в Телеграм, можно файлом в репо.

## Чего не ждут

- Идеального кода. Смотрим на ход мысли, а не на стиль.
- Переписывания архитектуры. Если у тебя есть что сказать про `вообще тут надо всё переделать` - напиши отдельным абзацем в отчёте, но фиксить не надо.

## Срок

Ориентировочно 2-3 дня.

## Что получишь, если пройдёшь

Полный доступ к n8n-инстансу, БД, MinIO, SSH на сервер, доку. Контекст по каждому пайплайну от меня лично в первый месяц - там нюансов больше, чем в любой доке.
